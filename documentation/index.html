Context and goals

What this service is

lazy-agent-service is the workspace's unified agent runtime. Since the prism exit (ee61164 "refactor: retire prism-service; lazy-agent-service is the only gateway", 2026-10-31) every LazyCat420 repo runs its agents here — nothing forwards to prism's :7777 any more. It is three services in one process on NAS port :5591:

  1. An agentic harness. The multi-turn tool-calling loop (AgenticLoopService → src/core/loop/) with context compaction, stall/loop guards, SSE streaming, and durable completions for Obsidian vault chat and trading runs. The self-improving harness2 loop (src/services/harness2/, POST /harness2/run) proposes, probes and composes harness trees and keeps an experience library per domain.
  2. An MCP tool server + registry. tool_schemas.json — 78 tools across trading (market data, screener, execution, whiteboard, watch desk, parameter governance, research scheduling), html-notes (21 + 5), shared (web search/extract, news, quality) and treesearch (cannabis research, 8) — is exposed over McpAdapter /mcp/sse + /execute and routed locally by ToolOrchestratorService / LocalToolRouter.
  3. A local-LLM router. DynamicModelResolver admits requests to the vLLM cluster (DGX Spark DeepSeek/GLM, Dell Qwen, Jetson Nemotron) with health-based fallback; wallgarden/JetsonGate protects the 2-slot Jetson; the shared /embed endpoint fronts EmbeddingGemma2 on the Jetson for every repo in the house.

What it is NOT

  • Not an order executor. Orders, policy gates and the paper ledger live in trading-service; this harness only runs the tool loop and never fabricates a tool answer.
  • Not a model host. Models run on external vLLM boxes (ch.04); this service only routes.
  • Not the trading cycle's TDD. The cycle spans four repos and is documented in trading-client/documentation/; see ch.00.
  • Not a general-purpose web proxy. scrape_url/web_search are tool-loop facilities with budgets and guards (ch.05, ch.12), not an open fetch API.

Goals in order of priority

  1. Correct tool loops. Every tool call is authorized (decideToolCall), schema-validated, repeat-guarded, and either executed or refused with an actionable error. A failed run ends failed; it never invents results.
  2. One gateway, no forks. All repos use this harness; parity work against prism was closed out (ch.10 ADR-01) and prism-service is retired.
  3. One catalog. A single generator owns tool_schemas.json (ch.05); the three repo copies stay byte-identical.
  4. Bounded resources. The Jetson's 2 inference slots, Exa's keyless rate limit, the shared embedding queue and per-run tool/scrape budgets are all guarded centrally.
  5. Evidence. Every request and tool call leaves a row or span (ch.07) so "did it run?" is answerable without rerunning it.

Non-negotiables

  • The harness never registers a stdio MCP command outside the operator allowlist (ch.12).
  • A restart during a trading cycle breaks in-flight desks: deploy only between cycles (ch.08).
  • docs/contracts/ is served as-is by ContractRoutes and copied by scripts/export-contracts.mjs; it is read by other repos and stays in place.

The harness execution loop

Gateway-hosted agent runs go through one loop: AgenticLoopService driving src/core/loop/ (CoreLoop.ts, ToolRunner.ts, MessageCompactor.ts, RunawayStreamWatch.ts, SpillBuffer.ts, ToolOutputSubstituter.ts), while trading cycle seats execute their multi-turn tool loop inside lazycat-sdk (AgentHarness), streaming directly through /vllm-shim/<box>/v1/chat/completions (ch.02, ch.04). harness2 adds a self-improving layer on top of AgenticLoopService. A turn is: model call → tool calls → tool results → next model call, until final answer, budget close, or a guard fires. The loop never fabricates a tool answer: a failed tool returns an error result to the model, and every completed or terminated run emits explicit loop honesty fields (S-01, LoopHonestyFields.ts): answerSource ("model" | "partial" | "synthetic"), finalizeReason ("COMPLETED", "CUT_OFF" on single length-cut turns without tool calls, "CUT_OFF_TWICE", "STEP_LIMIT", etc.), providerAttempts, and providerRetries.

Multi-turn tool calling

  1. Assemble: persona system prompt, memories/skills/workflows (retrieved via embeddings, ch.06), the tool catalog for this caller (ch.05).
  2. Call the model via DynamicModelResolver (ch.04). OpenAI-compatible recovery handles malformed tool calls: Qwen coder-format text tool calls in streamed content (5cb9ecf), and the <parameter=NAME> function-opener variant (55d55ed); recovered arguments are rebound with bindRecoveredToolArgs (TradingToolStream.ts).
  3. Validate every tool call against its schema. A type rejection names the received type and a 40-char safe preview (6b46ec2, ec4072b). Hallucinated names resolve to canonical tools through HALLUCINATED_TOOL_ALIASES + resolveToolName() in ToolRunner.ts (e.g. query_market_screener → screener_query).
  4. Authorize (decideToolCall, one decision everywhere), then dispatch through ToolOrchestratorService (ch.05).
  5. Repeat until the model answers without tool calls, the run budget closes, or a guard fires.

Context compaction

AgenticLoopService triggers pressure compaction at a configurable fraction of the context budget (default 0.6): compactToolResultsForPressure replaces older tool results with one-line placeholders ({compacted: true}), and when it fires, plan-style summary compaction (compactWithPlanSummary, the omp pattern) injects a mechanically derived [plan summary] block so the model can still cite what it saw. Overflow recovery retries after compaction instead of failing the run.

The other control loops on the platform

The tool loop above is the only agent loop, but two sibling services run their own control loops, and their timing explains behaviour seen from here.

spark-console reconciler (reconciler() in console.py, a daemon thread). After a 15 s boot settle it runs reconcile_at_boot() (bring the LLM up if its toggle is on; adopt a deployment that is already running) inside a try, so a boot failure can never kill the loop. Then every 30 s, under the operation lock:

  1. reconcile_remote_llms_locked() — keep the Dell boxes' standalone models in their desired state (ch.04).
  2. Auto-resume — restart a render-suspended LLM once the contending ComfyUI queues have been idle for 300 s (ch.04 render-permit).
  3. Drift adoption — an engine answering while the phase says otherwise is adopted as running; a running phase whose containers vanished is recorded as a CONTAINER_CRASH incident (autoheal_audit, GET /api/audit/crashes) and restarted, at most 3 times in 15 minutes (can_autoheal_restart()), after which the phase is left at error for a human.

Mode switching — POST /api/serving-mode/{new_mode}

Under the operation lock:

  1. An unknown mode → 400; the current mode → {"unchanged": true}.
  2. If anything is running (phase != "stopped" or any owned container exists), the outgoing deployment is fully stopped, containers gone, before anything else happens. Two deployments at once exceed unified memory and OOM the box (ch.10 ADR-16).
  3. state.serving_mode is saved, and the new mode's pi_model is written to omp-model. pi does not fail on an unknown model id — it sends it and the server 404s — so this file is what keeps the omp session talking to the model that is actually up.
  4. The omp session is restarted, because the MCP bridge reads serving_mode once at startup to decide whether worker render tools are safe (only in single).
  5. If the LLM toggle was on, the new deployment is started in place of the old one.

Callers of this harness see the switch as goldspark going down and coming back with a different model id; the resolver's real-time probe takes the box out of rotation while it is down, and VllmModelSyncService picks the new id up once it answers. bench-proxy.py is a separate process from the console on purpose: restarting the console never drops an in-flight completion.

Long text: bounded chunking

Text is split at Unicode character boundaries into ≤1,800 UTF-8 bytes per chunk; a request packs ≤8 chunks within 7,000 total UTF-8 bytes; chunk vectors are summed and L2-normalized into one document vector. Token-limit refusals are surfaced, never silently truncated. Index identity records the chunking/aggregation policy, model revision and dimensions — and vectors from different spaces never compare. Use the same client and policy for query and document sides.

Flow control

Calls serialize within the process; 60 s inference timeout; HTTP 429 honours numeric Retry-After, ≤3 attempts, ≤10 s delay; 503/quarantine surfaces immediately. The Jetson's own single-inference guard stays authoritative.

What consumes embeddings

  • Prompt assembly: agent memories, skills and workflows are retrieved by similarity, scoped to project + agent.
  • Memory extraction/consolidation: document/query tasks; dedup considers the latest 500 matching documents, dedups the latest 200.
  • Skills: document vector on save; query vector at selection; vectorless skills stay available as an unranked fallback.
  • Workflows: a successful trajectory (≥4 messages, ≥3 tool calls, success, session ids; 1-minute storage cooldown) is embedded for recall (latest 50 considered).
  • Conversation summaries: from title + compaction summary + linked memories, ≥6 messages, 5-minute cooldown, source capped at 2,000 chars.

  • Parallel average (aggregate_summary) divides the same qualifying tokens by the union of decode intervals, so overlapping time counts once and prefill/idle gaps are excluded.
  • Combined maximum is the highest observed output-token counter increase over the actual elapsed time between successful engine observations; it survives restarts and is an observed rate, not a hardware limit.
  • A serving-mode switch, or unknown proxy coverage, disables solo verification until a fresh proof succeeds (bench-concurrency-guard.py routes local :8001 calls through :8000).

ADR-01 — Every repo on our own harness; prism-service retired (2026-10-06 → 2026-10-31)

Decision. Every LazyCat420 repo runs its agents through this service's harness (/agent, /chat, /embed, /custom-agents), never through prism-service. Prism was first demoted to logging only (rows kept flowing to the shared prism.requests collection so audit readers kept working), then removed from the stack entirely on 2026-10-31 (ee61164): re-dialer, PrismProxyService, PrismAttribution and the PRISM_MCP_* compose variables deleted. Nothing forwards to :7777 anymore. Registration with prism had already gone (f2f78a4, PrismRegistrationService.ts deleted 2026-10-16). prism-service itself is never edited — it is Rodrigo Barraza's repo; Rod's projects keep using prism on their own. Consequences. lazycat-sdk harness_base_url() strips /prism-proxy so no production call can reach prism through a proxy; endpoint coverage is pinned by src/routes/__tests__/NativePrismExitRoutes.test.ts; the shared prism.custom_agents collection is read directly, so all 34 agents (trading V3 included) needed no migration.

ADR-02 — One tool-schema generator (2026-10-22)

Decision. The shards in tool_schemas/<owner_app>/*.json are the source of truth and one command, scripts/export_tool_schemas.py, turns them into the flat tool_schemas.json — and, with --out, byte-identical copies into the trading repos. The two-generator state before (which repo deployed last decided the shipped file; news_search lost its owner_app and was miscounted as a trading tool) is closed. Unknown CLI arguments are an error; the trading PRE_BUILD steps probe --supports-out and refuse a stale exporter. Proof. src/services/__tests__/ToolSchemaExport.test.ts + --check gate (ch.05, ch.09).

ADR-03 — Parity is measured through the real caller, never a log replay (2026-10-07)

Decision. Harness-vs-harness parity runs go through trading's own client code (trading-service scripts/harness/parity_check.py), same input to both loops. Log replays from prism.requests are forbidden as evidence: prism strips systemPrompt, enabledTools and autoApprove, and without autoApprove the ApprovalGate burns the full APPROVAL_TIMEOUT_MS = 120_000 per call — the exact 120 s gaps that once masqueraded as harness behavior. Synthetic probe-parity- cycles are refused cycle-escaping write tools by the bridge.

ADR-04 — One tool-authorization decision (2026-10-16)

Decision. Every gate — harness approvals, /chat function calling, the Live API, /v1/runs, plan approval, the post-write validator — funnels through the single decision decideToolCall (src/services/ToolAuthorization.ts), fed by PolicyEngine rules and applied by ApprovalGate.authorizeToolCalls. AutoApprovalEngine was removed: there is no second path that says yes. Trading tools additionally require the signed _lazy_trading_context; a forged one without the key is PERMISSION_DENIED (dispatchTool → authorizeTradingTool verifies the signature).

ADR-05 — LocalToolRouter repeat guards stay after the prism era (2026-10-31)

Decision. When prism-service was retired, the LocalToolRouter repeat-call guards from that era were kept as harness-side defense-in-depth: identical read-only tool calls within a run are reused, not re-paid (ebdda0d screener reuse, 260c020 run_tool_chain read-only reuse), and a repeat is not a TOOL_STALL failure. The guards no longer protect prism's Mongo; they protect the model's context window and the external APIs' rate limits — the same reason the trading-run scrape/tool budgets exist (ch.03).

ADR-06 — stdio MCP only from an operator allowlist (2026-10-22; retired Wave 4C)

Decision. (Superseded in Wave 4C: outbound MCP client, /mcp-servers, and MCPClientService were removed entirely; only the inbound McpAdapter /mcp/sse server remains.) POST /mcp-servers + connect were unauthenticated remote code execution: any caller could have the service spawn a command with the whole process environment. The fix is one guard — assertStdioAllowed in MCPClientService.connect() (repeated in createTransport) — and MCP_STDIO_COMMANDS: comma-separated absolute paths, exact match. Never list an interpreter or shell (node, npx, python, sh): row args stay caller-controlled, so -e re-opens the hole. Disabling a refused row (PUT enabled:false) stays allowed (ch.12).

ADR-07 — code_interpreter fails closed in an OS-locked child (2026-10-11)

Decision. The vm inside the service process was not a boundary (one escape was fixed in 6c05067). Each snippet now runs in a fresh node child: --permission (no grants), --disallow-code-generation-from-strings, 64 MB heap, empty env, cwd tmp, SIGKILL deadline, 1 MB output cap, ≤2 concurrent. A boot self-test inside a sandbox requires fs/net/dns/child/ worker/binding/codegen all denied; otherwise the interpreter reports CODE_INTERPRETER_UNAVAILABLE rather than run. Image is node:26-slim — Node 24/22's permission model does not lock the network. Proof is ablation: each attack must land with its wall off and fail with it on (scripts/benchmarks/sandbox-redteam.mts, 340140e + f2701c6).

ADR-08 — Measured gates; verify excludes Prettier (2026-10-29)

Decision. Quality is executable: a claim of "done" names a command. npm run verify (typecheck → lint → tests → dry → arch → prompt) blocks in CI; CRAP/complexity ratchets to 0 offenders; the ESLint complexity rule is error at 20. verify excludes prettier --check because the repo has never been Prettier-formatted (406 files) and a mass reformat would bury real diffs. The local pre-push hook belongs to the workspace secret scanner, so quality enforcement lives in .github/workflows/quality.yml. Sensors are deterministic and cheap: code_health measures submitted files in-process — no shell, FS or network (ch.09).

ADR-09 — Harness² follows upstream at every decision point (2026-10-22)

Decision. The recursive port keeps upstream's task schedule (4k-rollout/3k-stage budget, INV/DOM split, sequential checkpoints, parallel compose) and adopts upstream's decision points: the selection pool is the k finals only (a base output can no longer be "adopted" into the lesson store), k=1 delivers the single final with no selector call, reflection and library.add run only on a successful selection, an all-failed base stops with base-failed, and the library never reads a task's own entry. selectionPool: "mixed" keeps the old pool as an explicit opt-in. Evidence floors are upstream's (tool results ≥ 10,000 chars) with a 240,000-char mission budget before compaction. The loop is kept honest about its limits: cross-task library transfer measured +0.00, so production agents are not silently changed by it.

ADR-10 — Runs outlive the client (2026-10)

Decision. A dropped SSE connection never cancels a run. ActiveGenerationTracker + AgentSessionRegistry own the run lifecycle independently of the HTTP connection; /agent/stop is the only cancel. Obsidian completions are durable rows (PUT /obsidian-completions/:id) with SSE re-attach, and the first-party chat UI re-attaches to the durable record (9276e3f streams live reasoning, activeTools and SSE updates). Mobile clients closing a tab in the field must never lose a trading analysis.

ADR-11 — Catalog-first, model-agnostic harness (2026-10-29)

Decision. Per-model special cases come from the model catalog, not string patterns: getModelProfile reads limits, effort vocabulary and "does it think" from the catalog (family-name patterns are only the unlisted-model fallback); the openai provider's reasoning detection and the inworld provider's TTS steering read catalog flags. ADR-13 — Network MCP rows: refuse internal hosts unless allowlisted (2026-11-07; retired Wave 4C)

Decision. (Superseded in Wave 4C: outbound MCP client and /mcp-servers were removed.) ADR-06 closed stdio; sse/streamable-http rows could still point the service at 127.0.0.1, the NAS's own admin ports or 169.254.169.254. ADR-14 — Harness² library scope is opt-in per request (2026-11-07)

Decision. One experience library per domain stays the default, because lessons are meant to accumulate. A caller that needs isolation asks for it: isolateLibrary scopes the library by serving mode (<root>/<domain>/<mode>), libraryScope by run (.../<runScope>), and Library.forRun(domain, { root, mode, runId }) builds the same thing in code. Scope names that collide with the library's own layout (harnesses, runs, INDEX.md) throw. Proof: Harness2Library.test.ts TCK-1020 block (f8063bf).

ADR-15 — One TDD for every agents/* service (2026-11-07)

Decision. lazy-agent-service, scraper-service, spark-console and tts-service are documented in this one 13-chapter document instead of four. ADR-16 — spark-console never overlaps two deployments (2026-10, recorded 2026-11-07)

Decision. Unified memory on the Sparks holds one LLM deployment at a time. A serving-mode switch (POST /api/serving-mode/{new_mode}) fully stops the outgoing deployment — containers gone — before the new one starts, and a ComfyUI render that needs a box the LLM occupies is granted only after the LLM is torn down (POST /api/render-permit). Running both at once would OOM the box; a slower handover is the accepted cost (ch.04, ch.08).

/execute and the execute key

POST /execute (Exa web search + scrape proxy used by html-notes, LLMSortObsidian, treesearch, trading-client, lazycat-sdk, bittle-agent) is gated by requireExecuteKey (src/routes/ExecuteRoutes.ts): when EXECUTE_API_KEY is set, no key → 401, wrong key → 401, x-api-key or Authorization: Bearer → 200. SSRF: fetch and scrape

Outbound fetch (web extract, scrape_url) resolves against private-address blocks before the request; the trading bridge additionally enforces per-run scrape budgets — dead URLs are recorded dead for the run, refused without re-charging, and the per-run maps (including known-dead entries) are pruned with the other run state (a989f16). Text that is not a URL is not charged to the budget (174db2a). Redirect hops are re-checked on the scraper side (httpx response hook, Playwright document guard, and post-redirect UNSCRAPABLE_DOMAINS check) against metadata endpoints like 169.254.169.254 (crawl4ai was removed from scraper-service 2026-11-04). scraper-service also bounds per-worker request concurrency through AdmissionGate (SCRAPER_ADMISSION_INFLIGHT=8, SCRAPER_ADMISSION_WAITING=16, fast 429 + Retry-After: 5) and shares per-domain pacing across workers via SQLite WAL rate_limiter.db (C3, C4). A repeated read of the same URL within a run is reused, not re-fetched (ADR-05).

Snippet execution

code_interpreter never runs inside the service process (ADR-07): fresh node child per snippet with --permission and no grants, --disallow-code-generation-from-strings, empty env, 64 MB heap, SIGKILL deadline, 1 MB output cap, ≤2 concurrent, and a boot self-test that disables the tool outright if any capability probe comes back allowed. Image is node:26-slim in both Dockerfile stages — the permission model only locks the network on 26.

Secrets and config hygiene

.env.example documents every variable (MCP_STDIO_COMMANDS, EXECUTE_API_KEY, provider URLs); production reads secrets from the vault/deploy-kit chain. 9810c4f locked CORS to an explicit origin allowlist, hard-failed on a missing API key in production, and removed the hardcoded credential from config.ts. DB-name inputs pass the BAD_DB_NAMES guard (parity with trading-service's clean_db_name, a8a3319). The MCP OAuth/execute keys rotate without ever appearing in command output, and healthProbe.ts strips URL credentials before exposing upstream addresses on GET /health (S-13). Never open or print .env* from tooling or docs.
