The harness execution loop

Everything that runs an agent goes through one loop: AgenticLoopService driving src/core/loop/ (CoreLoop.ts, ToolRunner.ts, MessageCompactor.ts, RunawayStreamWatch.ts, SpillBuffer.ts, ToolOutputSubstituter.ts). harness2 adds a self-improving layer on top. A turn is: model call → tool calls → tool results → next model call, until final answer, budget close, or a guard fires. The loop never fabricates a tool answer: a failed tool returns an error result to the model.

Multi-turn tool calling

  1. Assemble: persona system prompt, memories/skills/workflows (retrieved via embeddings, ch.06), the tool catalog for this caller (ch.05).
  2. Call the model via DynamicModelResolver (ch.04). OpenAI-compatible recovery handles malformed tool calls: Qwen coder-format text tool calls in streamed content (5cb9ecf), and the <parameter=NAME> function-opener variant (55d55ed); recovered arguments are rebound with bindRecoveredToolArgs (TradingToolStream.ts).
  3. Validate every tool call against its schema. A type rejection names the received type and a 40-char safe preview (6b46ec2, ec4072b). Hallucinated names resolve to canonical tools through HALLUCINATED_TOOL_ALIASES + resolveToolName() in ToolRunner.ts (e.g. query_market_screener → screener_query).
  4. Authorize (decideToolCall, one decision everywhere), then dispatch through ToolOrchestratorService (ch.05).
  5. Repeat until the model answers without tool calls, the run budget closes, or a guard fires.

Context compaction

AgenticLoopService triggers pressure compaction at a configurable fraction of the context budget (default 0.6): compactToolResultsForPressure replaces older tool results with one-line placeholders ({compacted: true}), and when it fires, plan-style summary compaction (compactWithPlanSummary, the omp pattern) injects a mechanically derived [plan summary] block so the model can still cite what it saw. Overflow recovery retries after compaction instead of failing the run.

Routing rules and fallback policy

  1. Class first. Light/small roles prefer the Jetson; smart/large roles prefer Gold Spark (vllm-2). Vision needs a capable box; compression/summarization is light work.
  2. Health-gated admission. Only instances answering the real-time probe are eligible.
  3. Single-box fallback. If exactly one box is online, it takes all jobs — degraded but running, logged.
  4. Provider fallback. Otherwise the first allowed provider that is online takes the call; an empty model reply is surfaced, and prism-style in-loop retry behaviour was ported during the cutover (ch.10 ADR-01). Nothing here retries across boxes unboundedly; a box that fails its probe is out for the round.

Token budgets

  • Compaction pressure fires at a configurable fraction (default 0.6) of the model's context budget before overflow; a 24k output cap guards harness2 improver replies (a3993ea).
  • Per-conversation budgets (ConversationBudgetRegistry, CanonicalProviderBudget, BudgetPauseRegistry) let callers pause/resume a run at budget close; trading runs get a tool budget whose close also closes tool offering (ch.03).
  • Wallgarden and scheduled tasks resolve their model through the same resolver, so a background job can never starve an interactive run for boxes.

The Jetson wallgarden gate

The Jetson has two inference slots (max_num_seqs = 2); before the gate, browser-driven classify-candidates batches queued up to 24 requests on it (60–77 s to first token, 12 s browser aborts) and starved interactive work. The gate (320bd24; now the JetsonGate class in src/services/wallgarden/JetsonGate.ts, shared instance wallgardenJetsonGate):

  • caps concurrent Jetson LLM calls from Wallgarden at 2 (maxInFlight: 2, maxWaitMs: 90_000),
  • enforces strict priority with FIFO within each tier: P0 interactive/creative (brainstorm, similar, extract-topics) > P1 curation (judge-topics) > P2 background (taste-profile, recommend-channels),
  • rejects queued P1/P2 requests after 90 s with JetsonGateRejectedError (HTTP 503) so background traffic fails fast,
  • publishes live telemetry (maxInFlight, inFlight, queued, rejected) on GET /api/wallgarden/models.

POST /api/wallgarden/classify-candidates is disabled (returns {classifications: [], disabled: true} with zero LLM calls): candidate filtering is deterministic client-side plus the NAS grounding scorer. Unit coverage: src/services/wallgarden/__tests__/JetsonGate.test.ts + WallgardenService.test.ts (61/61 via testrun); deployed and verified on the NAS.

Explicit cloud provider/model selections remain supported and take precedence over provider defaults.

Two entry points, one queue

EntryShape

Index through this endpoint, never the Jetson directly: a separate process gets its own queue and collides — while one such job ran on 2026-10-06, every live /embed call failed HTTP 429 after its three retries. Keep batches small (trading sends 8).

Long text: bounded chunking

Text is split at Unicode character boundaries into ≤1,800 UTF-8 bytes per chunk; a request packs ≤8 chunks within 7,000 total UTF-8 bytes; chunk vectors are summed and L2-normalized into one document vector. Token-limit refusals are surfaced, never silently truncated. Index identity records the chunking/aggregation policy, model revision and dimensions — and vectors from different spaces never compare. Use the same client and policy for query and document sides.

Flow control

Calls serialize within the process; 60 s inference timeout; HTTP 429 honours numeric Retry-After, ≤3 attempts, ≤10 s delay; 503/quarantine surfaces immediately. The Jetson's own single-inference guard stays authoritative.

What consumes embeddings

  • Prompt assembly: agent memories, skills and workflows are retrieved by similarity, scoped to project + agent.
  • Memory extraction/consolidation: document/query tasks; dedup considers the latest 500 matching documents, dedups the latest 200.
  • Skills: document vector on save; query vector at selection; vectorless skills stay available as an unranked fallback.
  • Workflows: a successful trajectory (≥4 messages, ≥3 tool calls, success, session ids; 1-minute storage cooldown) is embedded for recall (latest 50 considered).
  • Conversation summaries: from title + compaction summary + linked memories, ≥6 messages, 5-minute cooldown, source capped at 2,000 chars.
  • Trading-service RAG: batch calls through /embed since 2026-10-06 (trading-service 9f29927f); it keeps versioned semantic_embedding + space rows in its own Mongo store.
  • /embed callers generally (src/routes/EmbedRoutes.ts, ConversationEmbeddingService, MemoryExtractor).

Not migrated: the LLMSortObsidian plugin still calls the Jetson directly with the legacy embeddinggemma alias and no task type (tracked as debt, ledger). Cloud embedding providers keep their own modality capabilities; the Jetson adapter is text-only.

Telemetry and metrics

Three independent evidence layers: OpenTelemetry spans for request timing, durable request rows for per-call audit, and tool-execution spans for per-tool latency/error metrics. "Did it run, how long, did it fail?" is always answerable from stored data, never from memory.

OpenTelemetry tracing

src/telemetry/otel.ts is loaded before the app — node --import ./dist/src/telemetry/otel.js dist/boot.js in both the Dockerfile CMD and npm start — and exports OTLP to the NAS observability stack: otel-collector :4318 → Tempo :3200 → Grafana :3300. Search Grafana/Tempo for service name = lazy-agent-service. (Beyla is not an option: the Synology kernel 4.4 predates eBPF; it crash-looped 270 times and was removed 2026-10-09.)

InstrumentationOne span records
http + expressone incoming request with its Express route and middleware
undicione outgoing fetch (vault, models, tools-service, …)
mongodbone command — shape only, never values (enhancedDatabaseReporting: false)
  • /health is not traced (Docker polls it every 30 s; spans would bury real traffic).
  • Fails safe: a missing package or dead collector changes nothing; boot logs [otel] tracing off: ….
  • Settings: OTEL_TRACING_ENABLED=0 disables; OTEL_EXPORTER_OTLP_ENDPOINT default http://10.0.0.16:4318; OTEL_SERVICE_NAME default lazy-agent-service.
  • Known gap: batches export every 5 s, so the last ≤5 s of spans can be lost on container stop (the app's own shutdown handlers exit without flushing). If it ever matters, sample (ParentBased(TraceIdRatioBased(0.1))) instead of switching tracing off.

npm run smoke:otel (scripts/otel-smoke.mjs) proves the wiring against a fake OTLP collector using the exact production load order, with a SMOKE_TRACING=0 control run so every check can fail: spans arrive, service name set, express route span, outgoing fetch span, and /health served-but-untraced (requested over a raw socket, the way Docker's wget does it).

Audit log — request rows

RequestLogger middleware writes a row for every handled request to the shared requests collection (the historical prism.requests shape, kept so dashboards and audits reading the collection keep working). Each row carries timestamp and createdAt (equal, pinned by RequestLoggerPrismParity.test.ts — prism-era fix d8a3c10, still the contract), project / username scope, tool/API name counts, and outcome. Trading's Monitor and the cycle audits read these rows; a missing createdAt silently hides runs from every time-based reader.

Per-tool metrics

Tool calls emit tool_execution spans into the telemetry-service SQLite DB (/app/data/telemetry.db, spans table: name, service_source, status, duration_ms, raw_json) — the only durable week-scale source, because container stdout is capped (json-file, max-size=10m, max-file=3 ≈ 1–1.5 h retention). Per-tool tables therefore report, per tool: calls, failures, fail %, p50/p95 ms, truncations, malformed args, top errors.

Caveats the metrics readers must know:

  • A failure row from [ToolRetryInterceptor] failed tool call(s): [tool(attempt:N)] counts even when the retry eventually succeeded (span status OK) — fail % is pre-retry.
  • Trunc counts results cut to the per-result limit (ch.03/05).
  • Cross-contamination refusals (Cross-contamination blocked: …) are real refusals with 100 %-of-that-tool failure share; they are guards working, not transport failures.
  • Trading per-tool rows also print to stdout ([lazycat.tool_registry] Tool Execution: <tool> by <agent> - OK|FAILED (<N>ms), lazycat-sdk tool_registry.py), but that is a window source, not history.

Benchmark baselines for read-only endpoints (400×4, NAS-local) sit at p50 ≈ 37–45 ms for Express/one-Mongo-read paths and are re-measured whenever tracing changes.

Decisions

Settled choices, each with the reason and the proof. Not edited afterwards — a changed decision gets a new entry saying it supersedes the old one. ADR-01, ADR-02 and ADR-05 are cited from other chapters; keep the numbers stable.

ADR-01 — Every repo on our own harness; prism-service retired (2026-10-06 → 2026-10-31)

Decision. Every LazyCat420 repo runs its agents through this service's harness (/agent, /chat, /embed, /custom-agents), never through prism-service. Prism was first demoted to logging only (rows kept flowing to the shared prism.requests collection so audit readers kept working), then removed from the stack entirely on 2026-10-31 (ee61164): re-dialer, PrismProxyService, PrismAttribution and the PRISM_MCP_* compose variables deleted. Nothing forwards to :7777 anymore. Registration with prism had already gone (f2f78a4, PrismRegistrationService.ts deleted 2026-10-16). prism-service itself is never edited — it is Rodrigo Barraza's repo; Rod's projects keep using prism on their own. Consequences. lazycat-sdk harness_base_url() strips /prism-proxy so no production call can reach prism through a proxy; endpoint coverage is pinned by src/routes/__tests__/NativePrismExitRoutes.test.ts; the shared prism.custom_agents collection is read directly, so all 34 agents (trading V3 included) needed no migration.

ADR-02 — One tool-schema generator (2026-10-22)

Decision. The shards in tool_schemas/<owner_app>/*.json are the source of truth and one command, scripts/export_tool_schemas.py, turns them into the flat tool_schemas.json — and, with --out, byte-identical copies into the trading repos. The two-generator state before (which repo deployed last decided the shipped file; news_search lost its owner_app and was miscounted as a trading tool) is closed. Unknown CLI arguments are an error; the trading PRE_BUILD steps probe --supports-out and refuse a stale exporter. Proof. src/services/__tests__/ToolSchemaExport.test.ts + --check gate (ch.05, ch.09).

ADR-03 — Parity is measured through the real caller, never a log replay (2026-10-07)

Decision. Harness-vs-harness parity runs go through trading's own client code (trading-service scripts/harness/parity_check.py), same input to both loops. Log replays from prism.requests are forbidden as evidence: prism strips systemPrompt, enabledTools and autoApprove, and without autoApprove the ApprovalGate burns the full APPROVAL_TIMEOUT_MS = 120_000 per call — the exact 120 s gaps that once masqueraded as harness behavior. Synthetic probe-parity- cycles are refused cycle-escaping write tools by the bridge.

ADR-04 — One tool-authorization decision (2026-10-16)

Decision. Every gate — harness approvals, /chat function calling, the Live API, /v1/runs, plan approval, the post-write validator — funnels through the single decision decideToolCall (src/services/ToolAuthorization.ts), fed by PolicyEngine rules and applied by ApprovalGate.authorizeToolCalls. AutoApprovalEngine was removed: there is no second path that says yes. Trading tools additionally require the signed _lazy_trading_context; a forged one without the key is PERMISSION_DENIED (dispatchTool → authorizeTradingTool verifies the signature).

ADR-05 — LocalToolRouter repeat guards stay after the prism era (2026-10-31)

Decision. When prism-service was retired, the LocalToolRouter repeat-call guards from that era were kept as harness-side defense-in-depth: identical read-only tool calls within a run are reused, not re-paid (ebdda0d screener reuse, 260c020 run_tool_chain read-only reuse), and a repeat is not a TOOL_STALL failure. The guards no longer protect prism's Mongo; they protect the model's context window and the external APIs' rate limits — the same reason the trading-run scrape/tool budgets exist (ch.03).

ADR-06 — stdio MCP only from an operator allowlist (2026-10-22)

Decision. POST /mcp-servers + connect were unauthenticated remote code execution: any caller could have the service spawn a command with the whole process environment. The fix is one guard — assertStdioAllowed in MCPClientService.connect() (repeated in createTransport) — and MCP_STDIO_COMMANDS: comma-separated absolute paths, exact match. Never list an interpreter or shell (node, npx, python, sh): row args stay caller-controlled, so -e re-opens the hole. Disabling a refused row (PUT enabled:false) stays allowed (ch.12).

ADR-07 — code_interpreter fails closed in an OS-locked child (2026-10-11)

Decision. The vm inside the service process was not a boundary (one escape was fixed in 6c05067). Each snippet now runs in a fresh node child: --permission (no grants), --disallow-code-generation-from-strings, 64 MB heap, empty env, cwd tmp, SIGKILL deadline, 1 MB output cap, ≤2 concurrent. A boot self-test inside a sandbox requires fs/net/dns/child/ worker/binding/codegen all denied; otherwise the interpreter reports CODE_INTERPRETER_UNAVAILABLE rather than run. Image is node:26-slim — Node 24/22's permission model does not lock the network. Proof is ablation: each attack must land with its wall off and fail with it on (scripts/benchmarks/sandbox-redteam.mts, 340140e + f2701c6).

ADR-08 — Measured gates; verify excludes Prettier (2026-10-29)

Decision. Quality is executable: a claim of "done" names a command. npm run verify (typecheck → lint → tests → dry → arch → prompt) blocks in CI; CRAP/complexity ratchets to 0 offenders; the ESLint complexity rule is error at 20. verify excludes prettier --check because the repo has never been Prettier-formatted (406 files) and a mass reformat would bury real diffs. The local pre-push hook belongs to the workspace secret scanner, so quality enforcement lives in .github/workflows/quality.yml. Sensors are deterministic and cheap: code_health measures submitted files in-process — no shell, FS or network (ch.09).

ADR-09 — Harness² follows upstream at every decision point (2026-10-22)

Decision. The recursive port keeps upstream's task schedule (4k-rollout/3k-stage budget, INV/DOM split, sequential checkpoints, parallel compose) and adopts upstream's decision points: the selection pool is the k finals only (a base output can no longer be "adopted" into the lesson store), k=1 delivers the single final with no selector call, reflection and library.add run only on a successful selection, an all-failed base stops with base-failed, and the library never reads a task's own entry. selectionPool: "mixed" keeps the old pool as an explicit opt-in. Evidence floors are upstream's (tool results ≥ 10,000 chars) with a 240,000-char mission budget before compaction. The loop is kept honest about its limits: cross-task library transfer measured +0.00, so production agents are not silently changed by it.

ADR-10 — Runs outlive the client (2026-10)

Decision. A dropped SSE connection never cancels a run. ActiveGenerationTracker + AgentSessionRegistry own the run lifecycle independently of the HTTP connection; /agent/stop is the only cancel. Obsidian completions are durable rows (PUT /obsidian-completions/:id) with SSE re-attach, and the first-party chat UI re-attaches to the durable record (9276e3f streams live reasoning, activeTools and SSE updates). Mobile clients closing a tab in the field must never lose a trading analysis.

ADR-11 — Catalog-first, model-agnostic harness (2026-10-29)

Decision. Per-model special cases come from the model catalog, not string patterns: getModelProfile reads limits, effort vocabulary and "does it think" from the catalog (family-name patterns are only the unlisted-model fallback); the openai provider's reasoning detection and the inworld provider's TTS steering read catalog flags. An unknown model takes the safe path (omit sampling, send max_completion_tokens). Qwen coder-format text tool calls are recovered in the openai-compat path and carry the signed trading context for allowlisted tools (5cb9ecf, 58f8a54, 55d55ed, b87dacb). Judges never grade their own author: CriticGate picks a different model of the same provider and reports judgeIndependent.

ADR-12 — /execute key: rollout before enforcement (2026-10-11)

Decision. POST /execute was LAN-open with 9 production callers. The key (EXECUTE_API_KEY, 64 hex, canonical home vault-service/projects.json → config, never in git) was deployed to every caller first — each sends x-api-key only when its env var is set — and enforcement was switched on last, verified live (no key → 401, keyed → 200, one full trading cycle with 0 denials after). Rotation is a script that never prints the key: scripts/rotate-execute-key.sh (a3944c3, enforcement 0c1c2b3). Rollout items that depend on a stopped container or a human paste are reported open, never silently skipped.

Security and dependencies

This service is the workspace's agent gateway: one Express process on the NAS at :5591 holding database URIs, provider keys, and the trading bridge. The rule at every boundary is the same — caller-controlled things (commands, URLs, keys, snippets) need an explicit, minimal allowlist, and each boundary's proof is a named test or script (ch.09).

stdio MCP guard

One guard: assertStdioAllowed in MCPClientService.connect() — called by the /:id/connect route, boot auto-connect (connectAllFromDB), reconnect, authenticate and the OAuth callback — and repeated in createTransport right before StdioClientTransport is built. A row is refused unless its exact command is on MCP_STDIO_COMMANDS (comma-separated absolute paths, documented in .env.example). Never list an interpreter (node, npx, python, sh, bash): a row's args stay caller-controlled and -e re-opens code execution. PUT enabled:false on a refused row is still allowed so an owner can turn someone else's row off. The refused-path tests use a payload that would write a marker file and prove nothing was spawned; the allowlisted test spawns a real fixture server and asserts no MONGO_*, DATABASE_URL or *_KEY variable reaches it. Open (TCK-1019): sse/streamable-http rows are still unauthenticated, so a caller can point the service at internal URLs (SSRF) — filed in the ledger, not fixed here.

/execute and the execute key

POST /execute (Exa web search + scrape proxy used by html-notes, LLMSortObsidian, treesearch, trading-client, lazycat-sdk, bittle-agent) is gated by requireExecuteKey (src/routes/ExecuteRoutes.ts): when EXECUTE_API_KEY is set, no key → 401, wrong key → 401, x-api-key or Authorization: Bearer → 200. The key's canonical home is vault-service/projects.json → top-level config (plus the deploy-kit and vault master .env copies that deploys copy); never in git. Rotation is scripts/rotate-execute-key.sh — writes all four places, restarts the vault, redeploys, verifies 401/200, copies to clipboard, never prints the secret (--no-deploy writes only).

SSRF: fetch and scrape

Outbound fetch (web extract, scrape_url, MCP sse connects) resolves against private-address blocks before the request; the trading bridge additionally enforces per-run scrape budgets — dead URLs are recorded dead for the run, refused without re-charging, and the per-run maps (including known-dead entries) are pruned with the other run state (a989f16). Text that is not a URL is not charged to the budget (174db2a). Redirect hops are re-checked on the scraper side (httpx response hook, Playwright document guard) against metadata endpoints like 169.254.169.254; crawl4ai remains a documented residual (it is not in the default ladder). A repeated read of the same URL within a run is reused, not re-fetched (ADR-05).

Snippet execution

code_interpreter never runs inside the service process (ADR-07): fresh node child per snippet with --permission and no grants, --disallow-code-generation-from-strings, empty env, 64 MB heap, SIGKILL deadline, 1 MB output cap, ≤2 concurrent, and a boot self-test that disables the tool outright if any capability probe comes back allowed. Image is node:26-slim in both Dockerfile stages — the permission model only locks the network on 26.

Secrets and config hygiene

.env.example documents every variable (MCP_STDIO_COMMANDS, EXECUTE_API_KEY, provider URLs); production reads secrets from the vault/deploy-kit chain. 9810c4f locked CORS to an explicit origin allowlist, hard-failed on a missing API key in production, and removed the hardcoded credential from config.ts. DB-name inputs pass the BAD_DB_NAMES guard (parity with trading-service's clean_db_name, a8a3319). The MCP OAuth/execute keys rotate without ever appearing in command output. Never open or print .env* from tooling or docs.
