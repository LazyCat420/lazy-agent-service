# Contract Ownership — what must not be deleted as "dead code"

`npm run quality:deadcode` (knip) reports unused files, exports and types.
Those findings are a **report**, not a delete list: some symbols are consumed by
processes outside this repo. Before deleting anything knip flags, check this
file and the owner table.

## Public surfaces of this service

| surface | source of truth | consumers |
|---|---|---|
| MCP server (`/mcp/sse` on `:5591`) | `src/services/McpAdapter*`, registration name fixed (see `ARCHITECTURE.md` Names) | prism dials in; clients discover tools at runtime |
| Tool catalog | `tool_schemas/*.json` → `tool_schemas.json` (generated by `scripts/export_tool_schemas.py`) | agents, `LocalToolRouter`, MCP clients, trading-service mirrors |
| HTTP API | `src/routes/*.ts` + `src/routes/__tests__` | trading-service, HTML-Notes, prism, portal, chat UI |
| Wire/contracts | `contracts/*.json` (`run-contract-v1.2`, `capability-registry-v1.2`, `profile-contract-v1.2`, `tool-contract-v1.2`, `error-codes-v1.2`), exported to `dist/contracts` and `dist/schemas` | every consumer above; `contracts-bundle-v1.2.0.json` is the published bundle |
| Runtime wire | `contracts/generated/runtime-wire-v1.json` (via `npm run export:runtime-wire`) | `@lazycat/agent-chat` client |
| Chat UI | `public/chat/app.js` (built by `npm run build:chat-ui`) | browser clients |
| Telemetry bootstrap | `src/telemetry/otel.ts` (loaded by `node --import` in `npm start`) | every deployed process — not importable-looking, never delete |
| Environment keys | `.env` keys read by `config.ts` / `boot.ts` | deploy-kit; names are stable |

## Owners

| area | owner | rule |
|---|---|---|
| everything in this repo | LazyCat420 | may change, with a contract version bump when a public surface changes |
| consumers (`prism-service`, `portal-service`, `tools-service`, `vault-service`, `workspace-service`, `components-library`, `lupos-bot`) | Rodrigo Barraza | read-only here; adapt with wrappers in LazyCat420's repos |
| `trading-service` | LazyCat420 | consumes the tool catalog and HTTP API; never deploy it over a live cycle |

## Deleting a knip finding

1. Confirm nothing outside the repo can reach it: grep the repo, then check the
   surface table above (a tool name or route path is a contract even if no
   in-repo importer exists).
2. Delete in a dedicated commit that names the knip finding, with the grep
   evidence in the message.
3. Never batch a contract file, `tool_schemas/*`, `contracts/*`, or
   `src/telemetry/otel.ts` into a bulk dead-code sweep.
